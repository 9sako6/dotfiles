# カード設計規約

## 1. 想起の単位

- 1カードにつき、思い出す対象を一つにする。
- 表面を読んで5〜15秒程度で答えられる粒度を目安にする。
- 列挙を丸ごと問わない。一項目ずつ分けるか、既知の項目を表面へ与えて残り一つを問う。
- 「どこで誰が運用する？」のような二重質問を避ける。疑問が二つなら分ける。
- 一つのノートから複数カードを作る形式は、復習量が増えることを確認してから使う。
- Basic、逆カード、Clozeのどれかへ固定しない。既存ノートタイプがなければ、一つの想起対象を問う一方向カードから始める。

## 2. 問題文

対象、具体的な条件、答えの種類を表面に書く。`これは？` や `何という？` だけで終わらせない。

基本形は次のとおり。

```text
識別力の高い具体的な定義 + 答えの種類 + を何と呼ぶ？
```

例:

- `1日の約定値を取引成立順に並べた記録を何と呼ぶ？`
- `障害時に書き込みを引き継ぐ待機系サーバーを何と呼ぶ？`
- `この症状が出たとき、最初に確認するログはどれ？`

略称、正式名、別名、表記を答えさせる場合は、求める回答形式も表面に書く。

`どこ？` は実際の場所を答える場合だけに使う。転送先、処理主体、所有者を問う場合は、`サービス`、`コンポーネント`、`プロセス` など、答えの種類を明示する。

公式説明やコード上の事実から離れすぎない。短くするために、近縁概念との違いを消さない。由来や具体例が記憶の手掛かりになる場合は残す。

日本語では、括弧は原則として全角の `（ ）` を使う。半角括弧はコード内に限る。

### 目的を書く

計測、比較、繰り返し、確認などの操作を問うカードでは、何を判断するための操作かを表面に書く。操作だけでは複数の目的が考えられ、正解の範囲が定まらない。

- 悪い例: `CSV処理を繰り返したとき、各回のGC後の推移で何を確認する？`
- 良い例: `一時的なピークと処理後まで残る増加を見分けるには、各回のGC後の値で何を確認する？`

目的を足した結果、一枚で目的と手順の二つを答えさせない。目的は表面で与え、短答では判断点だけを答えさせる。

### 疑問詞と短答を揃える

疑問詞と文末が要求する答えの種類を先に決め、その種類の短答を書く。

| 表面が求めるもの | 短答の形 |
|---|---|
| `どこに置く？` | 場所や位置 |
| `何が変わる？` | 変わる対象 |
| `どう変わる？` | 変化の方向や結果 |
| `何を確認する？` | 確認対象、または `〜か` で終わる判断点 |
| `どの値／項目／キー／識別子？` | 同じ種類の名称 |
| `できる？` | `できる／できない` |
| `なぜ？` | 理由 |

質問と短答で、値、識別子、式などの種類をずらさない。

## 3. 答えと補足

答えを先に置き、採点時に探さなくてよい形にする。説明、例外、由来、正式名称は、既存ノートタイプに適切な補足や参考フィールドがあればそこへ分ける。

表面の直後に短答を続けて読み、日本語の応答として成立するか確認する。意味は近くても種類が違う組み合わせを通さない。

略語は初出時に正式名称を確認できるようにする。ただし、その学習対象で既知と確認した汎用語まで毎回展開しない。

答えが長い場合は、複数の事実を一度に採点しようとしていないか確認する。長さ自体が必要な定型文やコードなら例外として扱う。

## 4. 前提知識と順序

本編で新しい語彙を使う前に、その語彙を学習者が説明できるか確認する。説明できなければ、手前の基礎カードを追加する。

技術領域では次の並びが使いやすい。

1. 製品に依存しない一般概念
2. 基盤や製品での実装名
3. 対象システムの実際の構成

これは例であり、対象に合わせて層を増減する。

個別事実が揃ったら、状況から知識を引き出すカードを加える。

- `この症状なら最初に何を疑う？`
- `この変更で先に確認する境界はどこ？`
- `なぜこの構成を選んでいる？`

名前当てだけで埋めず、理由、判断、障害対応を到達目標に合わせて混ぜる。

## 5. 重複と近縁概念

新しいカードを作る前に既存カードを確認する。

- 同じ事実を同じ想起方向で問うカードを重複させない。
- 表記が同じでも意味が違う概念は別カードにし、表面で区別できる条件を書く。
- 同義語、略語、表記違いは、通常使う名称の一枚へまとめる。別名を独立して思い出す必要がある場合だけ分ける。
- 上位概念と下位概念、状態と手続きなど、意味差があるものを同義語として統合しない。
- 近縁カードは共通点だけでなく、そのカードだけを正解にする差異を表面に入れる。

既出の事実を、応用やシナリオとして別の状況から問うことは重複とみなさない。

## 6. 根拠と変化

カードの事実は一次資料で確認する。コード、設定、仕様書、公式リファレンスを優先し、解説記事だけを根拠にしない。

台数、容量、料金、バージョンなど変わりやすい値は原則として避ける。値そのものの暗記が到達目標に必要なら、更新元を明確にしてから入れる。

既存ノートタイプに参考フィールドがあれば、復習時にも役立つ一次資料をそこへ残す。専用フィールドを勝手に増やさない。

## 7. レビュー

追加前に次を確認する。

- [ ] 各カードの事実を一次資料で確認した
- [ ] 思い出す対象が一つである
- [ ] 表面だけで対象と答えの種類が分かる
- [ ] 操作を問うカードでは、その操作で何を判断するのかが表面にある
- [ ] 疑問詞と文末が要求する答えの種類に短答が一致する
- [ ] 表面の直後に短答を続けて読んでも、自然な応答になる
- [ ] 近縁概念も正解にならない
- [ ] 答えが採点しやすい位置にある
- [ ] 未学習の前提語彙を放置していない
- [ ] 同じ事実の既存カードと重複していない

機械検査だけでは日本語のねじれを拾えない。カード本文を先頭から通読し、主語の省略、疑問文の衝突、括弧で補わないと成立しない問い、同じ語尾の連続を直す。

複数回答の疑いとして、少なくとも `それぞれ`、`いくつ`、`何と何`、`すべて`、`全て`、`の順で` を確認する。ヒットは機械置換せず、一枚ごとに判断する。
