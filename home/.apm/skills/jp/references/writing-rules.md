# 意味を正確にする

- 主述が噛み合っているか、述語から主語を逆に辿って確かめる
  - 「この鍵は部屋ごとに持つ」→「鍵は部屋ごとに分かれています」
  - 「牛乳はなくなったぶんを買いに行きます」→「牛乳がなくなったら買いに行きます」
  - 「この汚れなら洗濯で落ちます」→「この汚れなら洗濯すれば落とせます」
- 無生物主語に人間の動詞をさせない。モノやコトを主語に置いたら、行為者を名指しするか自動詞に組み替える
  - 「この荷物が玄関を占領しています」→「この荷物だけで玄関がほぼ埋まっています」
  - 「大雨が電車を止めました」→「大雨で電車が止まりました」
  - 「この靴が足を痛めます」→「この靴を履くと足が痛くなります」
  - 「予定が私たちを急がせます」→「この予定だと急ぐ必要があります」
- スレッドやプロセス、オプティマイザ、バッチのように、プログラム内で実際に動く主体はそのまま主語にしてよい。ここまで言い換えると逆に読みにくくなる
- 「待ち時間が重なる」「所要時間が縮む」「値段が上がる」のような自動詞は、無生物主語でも問題ない
- 比喩を使うなら、読み手が何が起きるか復元できるものにする。意味を具体的に取り出せない比喩は事実に置き換える
  - 「午後になると予定が雪だるまになります」→「午後になると予定が次々に増えます」
  - 「食費が家計にのしかかっています」→「食費が増えて、毎月の支出が予算を超えています」
- 確かめたことと、まだ確かめていないことを書き分ける。仕組みを説明しただけなのに、効果まで確認済みであるように書かない
  - 「窓を二つ開ければ空気は通りやすくなります。室温が何度下がるかは測っていません」
  - 「この置き方では通路が広くなりました。掃除のしやすさはまだ試していません」
- 判断の確信度を変えない。推測を断定にしたり、確認できている事実を曖昧にしたりしない
  - まだ確認できていないなら「Aが原因です」ではなく「Aが原因だと思います」
  - 確認できているなら「Aかもしれません」ではなく「Aです」

# 必要な情報だけを書く

- 演出的な動詞や言い回しを落とし、起きていることをそのまま書く
  - 「収納の余裕を食い潰します」→「収納に収まらなくなります」
  - 「予算を自分で超えてしまいます」→「予算を超えます」
  - 「締切を踏み抜きました」→「締切に間に合いませんでした」
- 当たり前の動作をなぞるだけのコメントや補足は消す。ただし、その動作が判断の根拠になっているなら残し、判断を書いている場所に置く
  - 「冷蔵庫に入れると冷えます」だけなら不要
  - 「常温では傷みやすいので、翌日食べる分も冷蔵庫に入れます」なら残す
- コメントや補足は、説明しているものの直前に置く。文章を並べ替えたあとも、どの文を説明しているのか迷わない位置になっているか確かめる
- 同じ主張を言い換えて繰り返さない。隣り合う項目が同じ結論なら、一つにまとめる
- 文章の進行を実況しない。次に何を書くかを予告するだけの文は消し、その内容をそのまま書く
  - 「次に具体例を見てみます」→具体例から始める
  - 「ここまでで問題点が見えてきました」→問題点をそのまま書く

# 表記を揃える

- 用語と定義を並べるときは全角コロンにする
  - 「所要時間：30分」
  - 「予算：5,000円」
- 日本語と英数字の間に半角スペースを入れない。ただし、数値と単位の間は慣習に従う
  - 「iPhone 版」→「iPhone版」
  - 「Web の」→「Webの」
  - 「1cm」→「1 cm」
